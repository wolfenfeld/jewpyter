In the [previous post](/machine-learning/2020-03-01-RL3-post/) we built Deep Q Learning and saw it converge to near-perfect performance on CartPole.
DQN works, but it has a known flaw baked into its update rule — one that causes it to systematically overestimate Q-values, and one that requires a single line of code to fix.
That fix is **Double DQN**.

# The Problem: Overestimation

Recall the DQN target:

<script type="math/tex; mode=display">y_t = r_t + \gamma \max_{a'} Q(s_{t+1}, a';\, \theta^{-})</script>

The target network picks the action with the highest Q-value in the next state and uses that value as the target.
These are the same operation — _selecting_ the best action and _evaluating_ how good it is — performed by the same network in a single step.

This is a problem.
Early in training, Q-value estimates are noisy.
Some actions have inflated estimates just by chance.
When we take the max over all actions, we systematically pick the action with the highest noise, not the action with the highest true value.
We then use that inflated estimate as the training target, which trains the network to produce even higher estimates, which inflates the max further.
The bias compounds.

A concrete example helps.
Suppose the true Q-values in the next state are all equal: 1.0 for every action.
The network has not learned this yet, so its estimates are noisy — say, [0.8, 1.6, 0.9].
The `max` picks 1.6, even though the true value is 1.0.
We use 1.6 as the training target.
Next time the network sees this state, it adjusts toward 1.6.
Now its estimates are [0.9, 1.5, 1.0] — closer together, but still inflated compared to the truth.
The `max` will keep pulling the target above the true value on every update, and the error never self-corrects.

In practice the true Q-values are not all equal, but the same mechanism applies: the max consistently selects the most-overestimated action, and using that value as the target reinforces the overestimation.
The result is Q-values that grow too large and a policy that overcommits to actions that look good on paper but are not actually good.
On simple environments like CartPole this may not matter much — the overestimation is uniform enough that the relative ranking of actions stays correct.
On harder environments it causes instability and poor final policies.

We can measure this directly.
The chart below tracks two quantities throughout training: the Q-value the network assigns to a fixed set of states (solid line), and the actual discounted return earned from those same states by running the current greedy policy to completion (dotted line).
If the estimates were accurate, the two lines would overlap.
The gap between them is the overestimation bias.

# The Fix: Decouple Selection from Evaluation

The root cause is using the same network for both choosing the action and scoring it.
The fix, introduced by van Hasselt et al. in 2015, is to split these two responsibilities across the two networks we already have.

**DQN** (both steps use the target network):

<script type="math/tex; mode=display">y_t = r_t + \gamma \, Q\!\left(s_{t+1},\; \underset{a'}{\arg\max}\; Q(s_{t+1}, a';\, \theta^{-});\; \theta^{-}\right)</script>

**Double DQN** (select with main network, evaluate with target network):

<script type="math/tex; mode=display">y_t = r_t + \gamma \, Q\!\left(s_{t+1},\; \underset{a'}{\arg\max}\; Q(s_{t+1}, a';\, \theta);\; \theta^{-}\right)</script>

The main network <script type="math/tex">\theta</script> selects which action to evaluate.
The target network <script type="math/tex">\theta^{-}</script> scores it.

To see why this is better, think about what the max operation does to noise.

The network's estimates are noisy — each one is roughly the true value plus some error that varies from update to update.
If you look at any single action in isolation, the errors do cancel out over time: sometimes the estimate is too high, sometimes too low, on average it converges.
But DQN does not look at actions in isolation.
It takes the max over all of them.

And here is the problem: the max always picks whichever action happened to get the most positive error this time.
Not the action with the highest true value — the action with the highest estimated value, which is the one whose noise was most inflated on this particular update.
An action that was underestimated never gets selected; by definition, only overestimated ones do.

A simple example makes this concrete.
Suppose two actions both have a true value of 1.0, and the network's estimates are noisy around that truth.
On one update the estimates come out [0.7, 1.4]: the max picks 1.4.
On another update they come out [1.3, 0.8]: the max picks 1.3.
The individual noise on each action cancels out over time — average of [0.7, 1.3] is 1.0, average of [1.4, 0.8] is 1.1 — but the max does not cancel.
It always returns the larger of two noisy numbers, so its expected value is always above 1.0, no matter how many updates you run.

This is not a coincidence or a quirk of the training setup.
It is a mathematical certainty: the expected maximum of noisy estimates is always greater than or equal to the true maximum.
More actions and more noise make it worse.
The result is a systematic upward pull on every training target — not occasional overestimates that average out, but a consistent bias that accumulates with every gradient step.

Double DQN breaks this by asking a different question: instead of "which action does the target network think is best?", it asks "the main network thinks action <script type="math/tex">a_2</script> is best — what does the target network think <script type="math/tex">a_2</script> is worth?"

This matters because of what causes the overestimation in DQN.
The target network selected <script type="math/tex">a_2</script> precisely because its own estimate of <script type="math/tex">a_2</script> was the highest.
That is circular: the network picked the action where it was most optimistic, and then used that same optimistic value as the target.
The selection and the evaluation are two expressions of the same error.

In Double DQN, the action is still selected by whoever is most optimistic — the main network picks <script type="math/tex">a_2</script> because it thinks 1.8.
But now the evaluation comes from the target network, which had no part in the selection.
The target network may also have noisy estimates; it is not more accurate in general.
What it lacks is a systematic reason to put <script type="math/tex">a_2</script> high.
Its estimate of <script type="math/tex">a_2</script> reflects its own noise, not the noise that caused <script type="math/tex">a_2</script> to be chosen.
If the two networks' errors are independent, the expected value the target network assigns to the selected action is lower than the value the selecting network would have assigned — because the selecting network, by definition, had an unusually high estimate of that action.

In concrete terms: the main network picks <script type="math/tex">a_2</script> with an estimate of 1.8 (true value is 1.0).
The target network, queried for that same action, gives 1.3 — not because it is wiser, but because it did not select <script type="math/tex">a_2</script>, so it has no reason to be especially optimistic about it.
The training target becomes <script type="math/tex">r + \gamma \cdot 1.3</script> instead of <script type="math/tex">r + \gamma \cdot 2.1</script>.

Over many updates, this consistently produces lower, more grounded targets, and the Q-values stop drifting upward.

# Implementation

The change is exactly one line in the training step.

**DQN target computation:**

```python
target = reward + gamma * target_network(next_state).max(dim=1)[0] * (1 - done)
```

**Double DQN target computation:**

```python
best_actions = main_network(next_state).argmax(dim=1)
target = reward + gamma * target_network(next_state).gather(1, best_actions.unsqueeze(1)).squeeze() * (1 - done)
```

Instead of taking the max directly from the target network, we first ask the main network which action it thinks is best, then ask the target network what that action is actually worth.
Everything else — the replay buffer, the target network refresh, the loss function, the game loop — stays identical.

# Results

On CartPole, both DQN and Double DQN solve the environment — CartPole is too simple for overestimation to cause real damage.
The chart below shows they reach similar final performance, with Double DQN showing slightly tighter variance across runs:

The real benefit of Double DQN shows up on harder environments where Q-value overestimation derails training entirely.
On Atari games, for instance, DQN's Q-values can grow orders of magnitude above the true values, while Double DQN keeps them grounded.

# Conclusion and Next Steps

Double DQN is the smallest possible fix to DQN — one line in the training step — but it addresses a real and systematic bias.
The key idea is that selection and evaluation are two separate questions, and using the same noisy estimator for both inflates the answer.
Splitting them across two networks with independent noise suppresses the bias at no extra cost.

The next extension in this direction is **Dueling DQN**, which changes the network architecture itself.
Instead of outputting Q-values directly, the network learns two separate quantities: how good it is to be in a state at all (the value), and how much better each action is compared to the average (the advantage).
The Q-value is their sum.
This decomposition makes learning more efficient, especially in states where the choice of action barely matters.
